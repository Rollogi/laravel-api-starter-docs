`rollogi/billing` follows [Semantic Versioning](https://semver.org/) and is versioned on its own, apart from the starter kit and `rollogi/core`. This page mirrors the package's `CHANGELOG.md`. See [Package releases](/releases/packages) for how a version is tagged and published.

## 1.0.0 - 2026-10-25

The first release. Requires PHP 8.5, `laravel/framework` `^13.32`, `rollogi/core` `^1.1`,
`laravel/cashier` `^16.5` and `stripe/stripe-php` 17.3 or later.

### Added

- `BillingAccount`, Cashier's only customer model, owned by a tenant or a person (one each), with
  `ResolveBillingAccountAction` to create it on first use, the `HasBillingAccount` trait for the
  user model and a `billingAccount` relation on `Tenant`.
- Cashier's subscriptions and items as UUIDv7-keyed `Subscription` and `SubscriptionItem` on
  `billing_accounts`, `billing_subscriptions` and `billing_subscription_items`; Cashier's routes
  are switched off.
- A fluent plan catalogue, `Billing::plan()`, with owners, monthly and yearly prices, per-seat and
  metered prices, feature keys, limits, trials and a free fallback plan, validated once the
  application has booted.
- `CurrentPlans` and `ResolveCurrentPlanAction`: the plan behind an owner's valid `default`
  subscription, falling back to its free plan once the subscription lapses.
- `PlanFeatureSource`, a Core `FeatureSource`: a feature any plan grants is on only when the
  current plan of the tenant or the acting user grants it.
- The `ConsumesLimit` contract and the `EnforcePlanLimit` stage, added to the write preset after
  `ReplayIdempotentCall`, which refuses a write past the plan's allowance with a `403`
  `plan-limit-reached` problem.
- Billing endpoints for the active tenant (`/api/tenants/current/billing`, `billing.view` and
  `billing.manage`) and for the signed-in person (`/api/account/billing`): the summary, the plans,
  Stripe Checkout, the billing portal, a SetupIntent and subscribing with Elements, and swapping,
  cancelling and resuming the subscription, with `409 billing-*` problems for the wrong state.
- `BillingGateway`, bound to `CashierGateway`, as the only way the package calls Stripe.
- Stripe webhooks through Core's inbound pipeline at `POST /api/integrations/stripe/webhook`
  (`StripeWebhookHandler`), applied on the queue with Cashier's handlers.
- The `billing.view` and `billing.manage` permissions, created by a migration and given to the
  global admin role; the `billing.subscriptions`, `billing.checkout` and `billing.elements` feature
  keys, added to the registry as defaults; `config/billing.php` for the Checkout and portal return
  pages.
- Per-seat and metered pricing: Checkout, Elements and plan swaps carry the base price, the seats
  beyond those included and each metered price (`BuildSubscriptionItemsAction`).
  `SyncTenantSeatsAction` keeps the seat quantity in line with the tenant's members through the
  rebindable `SeatCounter`, prorated on the next invoice. The application dispatches it on its
  membership events, and `billing:sync-seats` runs it daily for every subscribed tenant.
  `ReportUsageAction` sends Stripe meter events under the metered name while the plan bills it.
  A per-seat plan can only be sold to tenants, and the billing summary shows the seats paid for.
- Extension points for building on the package without forking it:
  - **Webhook events.** `StripeEventReceived` for every Stripe event, plus typed events for the
    ones Cashier leaves to the application (`StripeEvent`: invoices paid, failed or needing
    action, Checkout and async payments, mandates, paused and resumed subscriptions, trial
    endings, refunds and disputes), each carrying the account and owner it concerns.
  - **`SubscriptionAccess`** (default `StripeSubscriptionAccess`) decides what a subscription
    grants, blocks and allows. A paused subscription grants nothing, and a first payment still
    processing (`payment_pending`, tracked from Checkout and the first invoice) waits for
    `invoice.paid` unless `billing.access.grant_while_payment_pending` is set.
  - **`SubscriptionRequest`** carries everything a new subscription or swap sends Stripe, and
    `GatewayCustomisations` adjusts the Checkout session and subscription builder.
    `billing.checkout.payment_method_types` and `allow_promotion_codes` set the defaults.
  - **`BillingDetails`** (default `OwnerBillingDetails`) supplies the Stripe customer's name,
    email, address and locales from its owner. The owner is also sent as metadata.
  - **`PaymentOutcome` / `PaymentStatus`.** Subscribing and swapping answer `complete`,
    `requires_action` or `processing`.
- Stripe API errors become problems: `402 billing-payment-failed`, `422 billing-request-refused`,
  `502 billing-provider-error`.
- `billing.seats.exclude` leaves members out of the seat count by a column on the users table,
  such as the starter kit's API keys (`['kind' => 'machine']`).
- `ReportUsageAction::queue()` fixes each meter event's identifier and time when it is queued, so
  a retried report is not billed twice.
- The routes that change tenant billing also need a person, so a tenant API key can read billing
  but not pay, cancel or open the portal.
