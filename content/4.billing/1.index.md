`rollogi/billing` is optional Stripe billing for a project built on the starter kit. It runs on [Laravel Cashier](https://laravel.com/docs/billing) and `rollogi/core`, and installs as a [package module](/core/package-modules), so it wires its own routes, migrations, permissions and feature keys without you editing a registry.

It gives you:

- **A billing account** for a tenant or a person, which is Cashier's only customer model.
- **A plan catalogue** you declare fluently in PHP with `Billing::plan()`, validated once the application has booted.
- **Plan features and limits**: a plan switches the kit's [feature toggles](/kit/feature-toggles) on, and caps how many of something an owner may create.
- **Endpoints** for Stripe Checkout, the billing portal, Stripe Elements, and changing, cancelling and resuming a subscription, once for the active tenant and once for the signed-in person.
- **Per-seat and metered pricing**, with a daily sweep that keeps seat quantities in step.
- **Stripe webhooks** through Core's inbound webhook pipeline, applied on the queue, with typed Laravel events for the ones Cashier leaves to the application.
- **Extension points** for what Stripe is sent, what a subscription grants, who takes a seat and the customer details Stripe sees.

The current release is **1.0.0**. It requires PHP 8.5, `laravel/framework` `^13.32`, `rollogi/core` `^1.1`, `laravel/cashier` `^16.5` and `stripe/stripe-php` 17.3 or later.

## How it fits together

```
Billing::plan(...)            the catalogue, declared in an app module's boot()
        |
CurrentPlans                  the plan each owner is on, from its "default" subscription
        |                     (or its free plan), resolved once per request
        +-- PlanFeatureSource     a layer of FeatureManager: plan features
        +-- EnforcePlanLimit      a write-preset stage: plan limits
        |
BillingAccount                Cashier's customer, owned by a Tenant or a User
        |
BillingGateway                the only class that calls Stripe (CashierGateway)
```

Stripe tells the package what happened through `POST /api/integrations/stripe/webhook`, and Cashier's handlers keep the subscription rows in step.
