The package is built to be extended from an app module, without forking it. It binds its defaults with `bindIf` and `singletonIf`, and registers before app modules, so a binding in your module's `register()` wins.

## What Stripe is sent

New subscriptions and swaps travel to the gateway as a `SubscriptionRequest`:

| Property | Holds |
| --- | --- |
| `items` | Each Stripe price with its quantity, `null` for a metered price |
| `trialDays` | The trial, if the owner gets one |
| `paymentMethodTypes` | Such as `card`, `bacs_debit`, `sepa_debit`; empty leaves the choice to the Stripe Dashboard |
| `allowPromotionCodes` | Whether Checkout shows its promotion code box |
| `promotionCodeId` | A promotion code to apply |
| `currency` | The currency, when set |
| `metadata` | Stored on the Stripe subscription |

Change what reaches Stripe from a provider's `boot()` through `GatewayCustomisations`, without rebinding the gateway:

```php
use Laravel\Cashier\SubscriptionBuilder;
use Rollogi\Billing\Gateways\GatewayCustomisations;
use Rollogi\Billing\Gateways\SubscriptionRequest;
use Rollogi\Billing\Models\BillingAccount;

app(GatewayCustomisations::class)
    ->checkout(fn (array $session, SubscriptionRequest $request, BillingAccount $account): array => [
        ...$session,
        'payment_method_collection' => 'if_required',
    ])
    ->subscription(function (SubscriptionBuilder $builder, SubscriptionRequest $request, BillingAccount $account): void {
        $builder->withCoupon('launch');
    });
```

`checkout()` callbacks receive and return the Checkout session parameters. `subscription()` callbacks adjust Cashier's `SubscriptionBuilder`, which builds every new subscription, through Checkout or Elements. Both may be registered more than once and run in order.

`billing.checkout.payment_method_types` and `billing.checkout.allow_promotion_codes` set the defaults. `BillingGateway` itself stays the one class that talks to Stripe, and you can rebind it too.

## What a subscription grants

`SubscriptionAccess` answers three questions wherever the package would otherwise read Cashier's `valid()`:

| Method | Asks |
| --- | --- |
| `grantsPlan(Subscription $subscription): bool` | Whether the owner is on the subscription's plan, rather than its free plan |
| `blocksNewSubscription(Subscription $subscription): bool` | Whether it still stands in Stripe, so a second one would bill the owner twice |
| `allowsChanges(Subscription $subscription): bool` | Whether its plan, seats or cancellation may be changed now |

The default, `StripeSubscriptionAccess`, is described under [The current plan](/billing/plans#the-current-plan). Rebind it to grant past-due subscriptions, say, or to change what blocks a second one:

```php [app/Modules/Plans/PlansServiceProvider.php]
use Override;
use Rollogi\Billing\Access\StripeSubscriptionAccess;
use Rollogi\Billing\Contracts\SubscriptionAccess;
use Rollogi\Billing\Models\Subscription;

class GracefulSubscriptionAccess extends StripeSubscriptionAccess
{
    #[Override]
    public function grantsPlan(Subscription $subscription): bool
    {
        return $subscription->pastDue() || parent::grantsPlan($subscription);
    }
}

// in register()
$this->app->bind(SubscriptionAccess::class, GracefulSubscriptionAccess::class);
```

## Who takes a seat

`SeatCounter` has one method, `count(Tenant $tenant): int`. The default, `MemberSeatCounter`, counts every member less those `billing.seats.exclude` names. Rebind it for anything the config cannot say, such as counting only members with a particular role.

## The customer Stripe sees

`BillingAccount` sends Stripe its owner's details through the `BillingDetails` contract, whose `for(Model $owner): CustomerDetails` returns:

| Property | Holds |
| --- | --- |
| `name`, `email` | The customer's name and email |
| `address` | Stripe's address fields: `line1`, `line2`, `city`, `postal_code`, `state`, `country` |
| `locales` | Preferred locales |

The default, `OwnerBillingDetails`, reads the owner's name and email. `owner_type` and `owner_id` always go as metadata. Rebind the contract to add an address, locales or a tenant's billing contact. Direct debit mandates and Stripe Tax need them.

## Stripe's events

Listen for the events on the [Webhooks](/billing/webhooks#events) page. Each carries the account and owner it concerns.

## Configuration

The package merges `config/billing.php` in as defaults. To change a value, add a `config/billing.php` to the application with the top-level keys you change; each key you define replaces the package's whole value for it.

| Key | Default | Does |
| --- | --- | --- |
| `checkout.payment_method_types` | `[]` | Payment method types Checkout and Elements subscriptions offer. Empty leaves the choice to the Stripe Dashboard, which Stripe recommends |
| `checkout.allow_promotion_codes` | `false` | Whether Checkout shows its own promotion code box |
| `access.grant_while_payment_pending` | `false` | Grant the paid plan while the first payment is still processing |
| `seats.exclude` | `[]` | Members who never take a seat, as `column => value` pairs on the users table |
| `urls.tenant.success` | `/settings/billing?checkout=success&session_id={CHECKOUT_SESSION_ID}` | Where tenant Checkout returns on success |
| `urls.tenant.cancel` | `/settings/billing?checkout=cancelled` | Where tenant Checkout returns on cancel |
| `urls.tenant.portal_return` | `/settings/billing` | Where the tenant billing portal returns |
| `urls.person.success` | `/account/billing?checkout=success&session_id={CHECKOUT_SESSION_ID}` | Where personal Checkout returns on success |
| `urls.person.cancel` | `/account/billing?checkout=cancelled` | Where personal Checkout returns on cancel |
| `urls.person.portal_return` | `/account/billing` | Where the personal billing portal returns |

The return paths are appended to `FRONTEND_URL` (`app.frontend_url`, falling back to `app.url`). Stripe replaces `{CHECKOUT_SESSION_ID}` in the success path. Stripe's keys and webhook secret stay in Cashier's `config/cashier.php`; see [Installation](/billing/installation#stripe-keys).

## Public API

Semantic versioning covers:

- `Billing` and `PlanCatalogue`, `Plan`, `SeatPrice` and `MeteredPrice`;
- `BillingAccount`, `Subscription`, `SubscriptionItem`, the `HasBillingAccount` trait and the table names;
- `ResolveBillingAccountAction`, `ResolveCurrentPlanAction`, `CurrentPlans`, `PlanFeatureSource`, `PlanOwners`;
- the `ConsumesLimit` contract, the `EnforcePlanLimit` stage and its `plan-limit-reached` problem;
- the endpoints, their request and response shapes, and the `billing-*` problem types;
- `BillingGateway`, `CashierGateway`, `SubscriptionRequest`, `PaymentOutcome`, `PaymentStatus` and `GatewayCustomisations`;
- `SubscriptionAccess` and `StripeSubscriptionAccess`, `BillingDetails`, `CustomerDetails` and `OwnerBillingDetails`;
- the events in `Rollogi\Billing\Events`, the `StripeEvent` enum and the `payment_pending` column;
- `BillingProviderException`, `InvalidPlanException` and `UnknownPlanException`;
- `SeatCounter` and `MemberSeatCounter`, `BuildSubscriptionItemsAction`, `CountBillableSeatsAction`, `SyncTenantSeatsAction`, `ReportUsageAction` and `billing:sync-seats`;
- `StripeWebhookHandler`, the `billing.*` permissions and feature keys, `config/billing.php`, and `BillingServiceProvider`'s manifest key.

Classes not listed are implementation details, so build on the listed ones. Changes are recorded in the [changelog](/billing/changelog).
