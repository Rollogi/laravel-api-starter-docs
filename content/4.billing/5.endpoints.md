## Two sets of routes

Every endpoint exists twice, served by the same controllers. A route default, `billingOwner`, tells each controller which owner it acts for.

| Prefix | Middleware | Owner |
| --- | --- | --- |
| `/api/tenants/current/billing` | `api.tenant`, then `permission:billing.view` to read, or `person` and `permission:billing.manage` to change | The active tenant |
| `/api/account/billing` | `auth:api`, `person` | The signed-in person; they see only their own |

The tenant routes run inside the kit's [`api.tenant`](/kit/multi-tenancy) group, so the tenant comes from `X-Tenant` or the caller's sole membership. The routes that change tenant billing also carry `person`, so a tenant API key may read billing with `billing.view` but never pay, cancel or open the portal (`403 machine-forbidden`). The personal routes are account-level, like the kit's [Account module](/kit/account).

Every route is also behind a `feature:` key, so you can switch a way of paying off globally or per tenant.

## Routes

| Method and path | Feature | Does |
| --- | --- | --- |
| `GET /` | `billing.subscriptions` | The current plan, the latest subscription and the card on file (`200`) |
| `GET /plans` | `billing.subscriptions` | The plans for this kind of payer, without Stripe price ids, as `{data: [...]}` (`200`) |
| `POST /checkout` | `billing.checkout` | `{plan, interval}`: a Stripe Checkout URL (`201`) |
| `POST /portal` | `billing.checkout` | A Stripe billing portal URL (`201`) |
| `POST /setup-intent` | `billing.elements` | A SetupIntent client secret for Stripe Elements (`201`) |
| `POST /subscription` | `billing.elements` | `{plan, interval, paymentMethod}`: subscribes; `201` once settled, `202` while the payment needs the customer or is processing |
| `PATCH /subscription` | `billing.subscriptions` | `{plan, interval}`: swaps the plan, with Stripe's proration; `200`, or `202` when the change invoices at once and needs the customer or is processing |
| `DELETE /subscription` | `billing.subscriptions` | Cancels at the end of the period (`200`, the summary) |
| `POST /subscription/resume` | `billing.subscriptions` | Takes back a cancellation during the grace period (`200`, the summary) |

Paths are relative to either prefix. `interval` is `monthly` or `yearly`.

## Response shapes

### The billing summary

`GET /`, cancelling and resuming answer `BillingSummaryData`, and the payment results carry it as `billing`:

| Field | Type | Notes |
| --- | --- | --- |
| `plan` | plan or `null` | The [current plan](/billing/plans#the-current-plan) |
| `subscription` | subscription or `null` | The latest `default` subscription |
| `paymentMethodType` | string or `null` | For example `card` |
| `paymentMethodLastFour` | string or `null` | The last four digits on file |

A subscription has `status` (Stripe's status), `interval`, `valid` (whether it grants the plan), `onTrial`, `trialEndsAt`, `onGracePeriod`, `endsAt`, `quantity`, `seats` (paid seats beyond those included, `null` on a plan without seats) and `paymentPending`. Dates are ISO 8601.

### Plans

`GET /plans` lists every plan declared for this kind of payer, the free one included; the summary's `plan` has the same shape:

| Field | Notes |
| --- | --- |
| `key`, `label` | The plan's key and display name |
| `isFree` | Whether it is the free fallback |
| `intervals` | The intervals it has a price for: `monthly`, `yearly` |
| `seatsIncluded` | Seats included in the base price, `null` without seats |
| `metered` | The metered names it bills |
| `features` | The feature keys it grants |
| `limits` | Limit name to allowance, `null` for unlimited |
| `trialDays` | The trial a first subscription gets |

### Redirects and secrets

Checkout and the portal answer `{url}`. The setup intent answers `{clientSecret}`. Subscribing and swapping answer the [payment result](/billing/subscriptions#payment-results).

### Return pages

Checkout and the portal send the payer back to paths from `config/billing.php` on `FRONTEND_URL`, one set for tenants and one for people. The request cannot choose them, so a caller cannot point Stripe at a site of its choosing. See [Configuration](/billing/extending#configuration).

## Problem types

Errors are RFC 9457 problems, like the rest of the kit (see [HTTP conventions](/kit/http)).

### State conflicts (`409`)

| Type | When | Extensions |
| --- | --- | --- |
| `billing-already-subscribed` | Buying while the last subscription still stands in Stripe, including one incomplete or past due | |
| `billing-not-subscribed` | Changing with no subscription. Asking never creates a billing account | |
| `billing-subscription-locked` | Changing one whose payment is unsettled or that is paused | `subscription_status` |
| `billing-cancellation-pending` | Swapping the plan of a cancelled one in its grace period; resume it first | |
| `billing-already-cancelled` | Cancelling twice | |
| `billing-not-cancelled` | Resuming one that is not cancelled | |

### Stripe errors

Stripe API errors become `BillingProviderException` problems rather than `500`s:

| Status | Type | When | Extensions |
| --- | --- | --- | --- |
| `402` | `billing-payment-failed` | A declined card; `detail` is Stripe's message, written for the customer | `decline_code`, `stripe_code` |
| `422` | `billing-request-refused` | A request Stripe refuses | `stripe_code`, `param` |
| `502` | `billing-provider-error` | Stripe out of reach or failing | `stripe_code` |

Extensions with no value are left out.

### Other refusals

| Status | Type | When |
| --- | --- | --- |
| `403` | `plan-limit-reached` | A write past the plan's [limit](/billing/plans#limits) |
| `422` | `validation-failed` | An unknown plan, one sold to the other kind of owner, a free plan, or an interval with no price, on `plan` or `interval`. To move to the free plan, cancel the subscription |
| `403` | `machine-forbidden` | A tenant API key on a route that changes billing |
| `403` | `feature-disabled` | The route's feature key is off |

## Calling Stripe

Every Stripe call goes through the `BillingGateway` contract, bound to `CashierGateway`. Bind your own implementation in tests so nothing reaches Stripe:

```php
app()->instance(BillingGateway::class, new FakeBillingGateway);
```

`FakeBillingGateway` here is yours to write: the contract's methods are `checkoutUrl()`, `portalUrl()`, `setupIntentSecret()`, `subscribe()`, `swap()`, `updateSeats()`, `reportUsage()`, `cancel()` and `resume()`.
