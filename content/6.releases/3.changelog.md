This is a summary of the kit's `CHANGELOG.md`, which the [release workflow](/releases) writes when a release is published. The kit follows [Semantic Versioning](https://semver.org/) and the changelog follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

Changes on `main` that will go out with the next kit release.

- **Core 1.1.** The kit requires `rollogi/core` `^1.1`, which adds feature sources (a `FeatureSource` decides a feature between the overrides and the config default) and `StagePreset` (a package inserts a stage into every service's preset). `feature:list` shows which layer decided each feature.
- **Optional packages developed in the repository.** `rollogi/billing` (Stripe billing on Cashier) and `rollogi/nuxt-ui` (server-driven screens for a Nuxt UI renderer) live in `packages/billing` and `packages/nuxt-ui`, each with its own CI job. The kit does not require either, the release archive leaves both out, and every upstream sync drops them with Core:

  ```bash [Terminal]
  git rm -r -q -f --ignore-unmatch packages/core packages/billing packages/nuxt-ui
  ```

- **Package publishing.** `split-billing.yml` and `split-nuxt-ui.yml` publish the two packages from `billing-v<semver>` and `nuxt-ui-v<semver>` tags, and `prepare-package-release.yml` dates a package's changelog and merges it into `develop`. See [Releasing the packages](/releases/packages).
- **Admin gets every API permission.** `RolesAndPermissionsSeeder` gives the `admin` role every `api` permission rather than a fixed list, so permissions a package creates in a migration (such as billing's `billing.view` and `billing.manage`) reach admin too. The `user` role keeps its list.
- **Dependencies.** `dedoc/scramble` requires `^0.13.49`, since older releases loop on framework 13.x past 13.24, and the development tools take patch updates.

## 2.0.0

Released 2026-10-25. Requires `rollogi/core` 1.0.0.

### Breaking changes

::warning
2.0 moves Core into a package and merges the `Team` module into `Tenants`. A 1.x project moves across with `UPGRADE.md` in the kit's repository, and migrations rename the stored permissions, feature overrides, API key scopes, notification preferences and webhook subscriptions.
::

- **Core is the `rollogi/core` package.** `app/Core` moved to `packages/core/src` and its namespace from `App\Core` to `Rollogi\Core`; a project installs it from the private `Rollogi/core` repository. Imports of `App\Core\...` in your modules become `Rollogi\Core\...`. Core's fourteen config files are merged in as defaults, and you publish the ones you change with `php artisan vendor:publish --tag=rollogi-core-config`. See [rollogi/core](/core).
- **`Team` is merged into `Tenants`.** Member, invitation, role, permission, activity and API key routes move from `/api/team/...` to `/api/tenants/current/...`; accepting an invitation is `POST /api/invitations/{token}/accept` and leaving is `DELETE /api/tenants/current/membership`. The `users.*` permissions become `members.*`, the `team.*` feature keys and webhook events become `tenants.*` and `tenant.*`, and `config/team.php` becomes `config/tenants.php`. See [Tenants](/kit/tenants).
- **Error bodies** are RFC 9457 problem documents with no `message` key; the text is in `detail`. See [HTTP conventions](/kit/http).
- **Sign-in.** `POST /api/auth/login` answers `202` with a challenge when the account has two-factor enabled, `POST /api/auth/logout` revokes the current access token only, and the minimum password length rises from 8 to 12 characters.
- `FORCE_HTTPS` and `HSTS_MAX_AGE` move from `config/security.php` to Core's `http` config, under the same variables.
- The `DispatchAfterCommit` stage is removed; call `$this->afterCommit()` inside `handle()` instead.

### Added

- **Service pipeline.** A default write preset and `ReadService`, `stagesWithout()`, generic typed services, `afterCommit()` and `failed()`, a `ServiceInvocation` with lifecycle events, idempotent writes under an `Idempotency-Key`, and the `EmitMetric`, `InvalidateCacheTags` and `IndexForSearch` stages. See [Service pipeline](/core/service-pipeline).
- **Off the request.** `dispatch()`, `dispatchAfterCommit()`, `dispatchSync()`, `chain()`, `batch()` and `fake()` on actions and services, with the tenant, actor and request id restored on the worker. See [Actions](/core/actions).
- **Generators.** `make:module` and `make:use-case`. See [Use cases](/kit/use-cases).
- **Authentication.** Passkeys (WebAuthn), magic links, TOTP two-factor with recovery codes and a per-tenant requirement, social sign-in for Google, GitHub, Microsoft and Apple, session management, change password, and recorded login attempts. See [Authentication](/kit/authentication).
- **Tenants.** Tenant lifecycle and settings endpoints, operator commands (`tenant:create`, `tenant:list`, `tenant:add-member`, `tenant:suspend`), suspension, tenant-defined roles, the activity stream and tenant API keys as machine members with scoped tokens. See [Tenants](/kit/tenants).
- **Account module.** Rename, verified email change, deletion and a JSON export. See [Account](/kit/account).
- **Outbound webhooks** with signed, retried, replayable deliveries. See [Webhooks](/kit/webhooks).
- **Notifications.** An in-app inbox beside Firebase push. See [Notifications](/kit/notifications).
- **HTTP.** ETags and `304`s, sorting and filtering, `API-Version`, deprecation headers and `Accept-Language`. See [HTTP conventions](/kit/http).
- **Operations.** `GET /api/health`, retention for every audit table, a production `Dockerfile` on the Rollogi PHP images, a development container, Octane on FrankenPHP, security headers, CORS restricted to the frontend origin, and trusted proxies. See [Deployment](/kit/deployment) and [Auditing](/kit/auditing).
- **Portability and releases.** MySQL and PostgreSQL test databases with `composer test:mysql`, `test:pgsql` and `test:all`, CI on all three databases, and the release workflow described in [Releasing the kit](/releases).

### Fixed

- The test suite no longer fails on a checkout without Passport keys, and no longer overwrites a developer's keys on every run.
- `METRICS_DRIVER=null` and `SEARCH_DRIVER=null`, as `.env.example` ships them, no longer make every service call fail.
- Permission pivot tables can be created on MySQL and accept global (`tenant_id = null`) assignments on PostgreSQL. Existing PostgreSQL projects are converted by `2026_10_22_000000_rework_permission_pivot_keys` on their next `php artisan migrate`.
- Registering with an email that lost a concurrent insert race no longer returns `500` on PostgreSQL.
