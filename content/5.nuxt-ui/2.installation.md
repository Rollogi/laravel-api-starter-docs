A project created from the starter kit does not include the package. You add it when a frontend renders its screens.

## Requirements

- PHP 8.5 and `laravel/framework` `^13.32`
- `rollogi/core` `^1.1`, which the kit already requires
- `spatie/laravel-data` `^4.23` and `spatie/laravel-query-builder` `^7.3.2`, which Composer installs with the package
- access to the private `Rollogi/nuxt-ui` repository

## Add the repository

Add a VCS repository to the project's `composer.json`, after the ones it already lists:

```json [composer.json]
{
    "type": "vcs",
    "url": "https://github.com/Rollogi/nuxt-ui",
    "only": ["rollogi/nuxt-ui"]
}
```

The GitHub token that reads `Rollogi/core` reads this one too, if it has access to both (`composer config --global github-oauth.github.com <token>`, or `COMPOSER_AUTH` in CI). Then:

```bash
composer require rollogi/nuxt-ui:^1.0
```

There are no migrations. The package's `composer.json` lists `Rollogi\NuxtUi\NuxtUiServiceProvider` under `extra.laravel.api-starter-modules`, so the kit's `ModuleServiceProvider` registers it before the application's own modules. See [Package modules](/core/package-modules).

## What the provider wires

- the four [`/api/ui` routes](/nuxt-ui/screens#endpoints), inside the `api` middleware group;
- `UiRegistry` as a singleton and the request's nav announcements as a scoped binding;
- the private `teams.{teamId}.nav` broadcast channel on the `api` guard;
- the `ui-user` rate limiter, for requests with no tenant, on the kit's `rate-limiting.tenant` window;
- `ResolveOptionalTenant` ahead of `ThrottleRequests` in the middleware priority list, so the limiter can key on the tenant;
- `config/nuxt-ui.php`, merged as defaults and publishable with the `rollogi-nuxt-ui-config` tag (see [Configuration](/nuxt-ui/configuration)).

## Broadcasting

Live nav badges are optional. If you want them, the host owns the broadcasting auth route, and that route must resolve the tenant (the client sends `X-Tenant`) or every subscription is refused. Register it from an app module provider's `boot()`:

```php
Broadcast::routes(['prefix' => 'api', 'middleware' => ['api', 'api.tenant']]);
```

Configure a broadcaster (Reverb, Pusher or similar) and run a queue worker, because the announcement is a queued broadcast. See [Navigation](/nuxt-ui/navigation#live-updates).

## Octane

Under Octane, add `UiRegistry` to `octane.warm`. It holds only what providers register at boot, so warming it is safe and saves rebuilding it per request:

```php [config/octane.php]
use Rollogi\NuxtUi\Support\UiRegistry;

'warm' => [
    ...Octane::defaultServicesToWarm(),
    UiRegistry::class,
],
```

## A first screen

With the package installed, register a page from an app module's provider and fetch it:

```php [app/Modules/Invoices/InvoicesServiceProvider.php]
use Rollogi\NuxtUi\Support\UiRegistry;

public function boot(): void
{
    $this->callAfterResolving(UiRegistry::class, function (UiRegistry $registry): void {
        $registry->page('invoices.list', InvoicesPage::class, path: '/invoices');
    });
}
```

```bash
curl -H 'Authorization: Bearer <token>' -H 'X-Tenant: <tenant-uuid>' \
  https://<your-api>/api/ui/pages/invoices.list
```

[Screens and endpoints](/nuxt-ui/screens) shows what `InvoicesPage` looks like.
