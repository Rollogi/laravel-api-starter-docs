A `Table` is a node like any other, made with an id, the source its rows come from, a mode and its columns:

```php
Table::make('invoices', 'invoices', 'server', ...$columns);
```

| Mode | Rows | Sorting, filtering, search |
| --- | --- | --- |
| `client` | A key of the source's data, named with `rowsFrom()` | In the browser; search with `searchKeys()` |
| `server` | The source *is* the page your endpoint returns | Through the query string, applied by `ApplyListQueryAction` |

## Declaring a server table

The same definition serves the screen and the endpoint behind it, so keep it in its own class:

```php [app/Modules/Invoices/Ui/InvoicesTable.php]
use Rollogi\NuxtUi\Builder\Tables\BadgeColumn;
use Rollogi\NuxtUi\Builder\Tables\DateRangeFilter;
use Rollogi\NuxtUi\Builder\Tables\EnumFilter;
use Rollogi\NuxtUi\Builder\Tables\NumberColumn;
use Rollogi\NuxtUi\Builder\Tables\RangeFilter;
use Rollogi\NuxtUi\Builder\Tables\RelativeTimeColumn;
use Rollogi\NuxtUi\Builder\Tables\Sort;
use Rollogi\NuxtUi\Builder\Tables\Table;
use Rollogi\NuxtUi\Builder\Tables\TextColumn;

class InvoicesTable
{
    public static function make(): Table
    {
        return Table::make(
            'invoices',
            'invoices',
            'server',
            TextColumn::make('number')->sortable(),
            BadgeColumn::make('status')->enum(InvoiceStatus::class, ['paid' => 'success'])->filter(EnumFilter::multiple(InvoiceStatus::class)),
            NumberColumn::make('total')->sortable()->filter(RangeFilter::make()->min(0)),
            TextColumn::make('customerName', 'Customer')->from('customers.name', 'customer_name')->nullable(),
            TextColumn::make('notes')->nullable()->hideable(true),
            RelativeTimeColumn::make('createdAt', 'Raised')->sortable()->filter(DateRangeFilter::make()),
        )
            ->model(Invoice::class)
            ->leftJoin('customers', 'customers.id', 'invoices.customer_id')
            ->search(['invoices.number', 'invoices.notes'], ['customer' => ['name']], 'Search invoices')
            ->defaultSort(Sort::desc('createdAt'))
            ->perPage(10, 25, 50);
    }
}
```

The definition is checked when it serialises or runs, and a mistake throws a `LogicException` naming the table and column. Among the checks:

- a table needs columns, each key once, and a default sort only on sortable columns;
- a server table has no `rowsFrom()`, and a client table uses `searchKeys()`, not `search()`;
- a column maps to a `snake_case` column, and a joined column names `table.column`, has a plain alias and reads a table the table joins;
- a nullable column is sortable only through `sortExpression()` (for example `COALESCE(invoices.rank, -1)`), and a nullable joined column cannot be sortable, because a cursor cannot page past nulls;
- a column cast with sub-second precision cannot be sortable, because cursor values drop microseconds;
- with `baseColumns()`, every base column a column shows must be selected.

### Columns

`TextColumn`, `NumberColumn`, `BooleanColumn`, `BadgeColumn`, `DateTimeColumn`, `RelativeTimeColumn`, `UserColumn` and `LinkColumn` (`make($key, $label, $to)`, with `rowLink()`) are made with a camelCase key and an optional label. In server mode the key maps to the `snake_case` column on the base table (`createdAt` reads `invoices.created_at`) unless you say otherwise:

| Method | Does |
| --- | --- |
| `column($column)` | Reads a differently named base column |
| `from($relationColumn, $alias)` | Reads a joined column, selected under an alias |
| `sortExpression($sql, $alias)` | Sorts by a SQL expression, such as `COALESCE(invoices.rank, -1)` |
| `nullable()` | Declares the column nullable; see the sorting rules above |
| `sortable()` | Allows sorting by it |
| `filter(TableFilter $filter)` | Attaches a filter |
| `hideable($hiddenByDefault = false)`, `mobile($placement)`, `emptyText()`, `label()` | Presentation |

`BadgeColumn` maps values to colours with `enum($enum, $colors)` or `options($options)`.

### Filters

| Filter | Made with | Sent as |
| --- | --- | --- |
| `EnumFilter` | `EnumFilter::single($enum)`, `EnumFilter::multiple($enum)` | One case, or several |
| `OptionsFilter` | `OptionsFilter::make($labels)`, with `multiple()` and `orNull($value, $label)` | Option values; `true` and `false` match options with those names |
| `BooleanFilter` | `BooleanFilter::make()`, `BooleanFilter::presence()` | A boolean, or whether the column is set |
| `RangeFilter` | `RangeFilter::make()`, with `min()` and `max()` | `from,to` |
| `DateRangeFilter` | `DateRangeFilter::make()` | `from,to`, as whole days |

Filters arrive as `filter[<column key>]=<value>`, and the search box as `filter[search]`.

### The rest of the table

`join()` is an inner join, which leaves out a row with no match. Use `leftJoin()` for a nullable foreign key, so a row with no match stays in the list, and declare the columns read through it `->nullable()`.

`baseColumns()` selects only the base columns you name (plus the key), so a list never fetches large columns it does not show. `multiSort()`, `defaultSort(Sort::asc(...), Sort::desc(...))` and `perPage(...)` shape sorting and paging; `rowActions()`, `bulkActions()`, `expand()`, `emptyState()` and `noResults()` shape the table around the rows.

### Search

`search($columns, $relations, $placeholder)` searches the base table's qualified columns, and a relation's columns through `whereHas`. It runs on PostgreSQL (`ILIKE`), MySQL, MariaDB and SQLite (`LIKE`, case-insensitive under their default collations), with the search term's wildcards escaped.

## The endpoint behind it

The table's source is your own list endpoint. Build `ListQueryData` from the request and hand it to `ApplyListQueryAction` with a query over the table's model:

```php
use Rollogi\NuxtUi\Actions\ApplyListQueryAction;
use Rollogi\NuxtUi\Data\ListQueryData;

$query = ListQueryData::fromRequest($request);   // filter[...], sort, cursor, per_page

$page = ApplyListQueryAction::run(Invoice::query(), InvoicesTable::make(), $query);
```

The action:

- selects the base columns, joins and aliases the table declares;
- applies the declared filters, sorts and search with `spatie/laravel-query-builder`, so anything not declared is refused;
- cursor-paginates with the key as a tiebreaker, using Core's `cursor` and `per_page` (clamped to `pagination.per_page.max`);
- checks a cursor against the order columns, and answers `400` for one that does not fit ("Start again from the first page");
- answers `400` for filters not sent as `filter[name]=value`, or a `sort` sent more than once.

It returns a `ResolvedCursorPaginator`, whose next and previous cursors were read from the query rows, so they survive mapping the rows to Data objects. Return the page from your controller as your other cursor-paginated endpoints do.

Scoping still applies: pass a query the tenant scope already filters (a `BelongsToTenant` model under `api.tenant`), and add any conditions of your own before the action runs. `ListQueryData::withDefaultFilter($key, $value)` sets a filter the caller did not send.

## Testing a table

`Rollogi\NuxtUi\Testing\TableAssertions::assertColumnsExist($table)` checks, against the real schema, that every sort and filter column exists, that no alias shadows a base column (which would make the cursor read the wrong value), and that every declared nullability matches:

```php [tests/Feature/Invoices/InvoicesTableTest.php]
use Rollogi\NuxtUi\Testing\TableAssertions;

it('declares only columns the schema has', function (): void {
    TableAssertions::assertColumnsExist(InvoicesTable::make());
});
```

Run it on every database your CI runs, since nullability and collation differ between them.
