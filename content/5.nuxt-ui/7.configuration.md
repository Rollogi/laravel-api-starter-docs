## Publishing the config

The package merges its `config/nuxt-ui.php` in as defaults. Publish it only to change something:

```bash
php artisan vendor:publish --tag=rollogi-nuxt-ui-config
```

## Options

| Key | Env | Default | Does |
| --- | --- | --- | --- |
| `schema_version` | `NUXT_UI_SCHEMA_VERSION` | `null` | The `uiVersion` reported on every manifest and screen. `null` reports `UiSchema::VERSION` |
| `tenant_middleware` | | The kit's `EnsureTwoFactorSatisfied`, where it exists; otherwise `[]` | Middleware run after the tenant is resolved on every `/api/ui` request that has one |
| `nav_channel_abilities` | | `[]` | Abilities that let a member listen on the nav channel. Empty lets every member of the active tenant listen |

### `tenant_middleware`

This list is the package's stand-in for the rest of the kit's `api.tenant` group, so a tenant's requirements hold on `/api/ui` as on its other routes. In a kit project it defaults to `App\Modules\Auth\Http\Middleware\EnsureTwoFactorSatisfied`, so a tenant that requires two-factor answers `403 two-factor-required` here too. Add any other per-tenant requirement of yours:

```php [config/nuxt-ui.php]
use App\Modules\Auth\Http\Middleware\EnsureTwoFactorSatisfied;
use App\Modules\Compliance\Http\Middleware\EnsureTermsAccepted;

'tenant_middleware' => [
    EnsureTwoFactorSatisfied::class,
    EnsureTermsAccepted::class,   // your own
],
```

Each middleware must return a response. `TenantFree` screens and a manifest served with no tenant skip the list, like the kit's account-level routes. See [Tenancy](/nuxt-ui/screens#tenancy).

### `nav_channel_abilities`

See [The channel](/nuxt-ui/navigation#the-channel). List the abilities whose lists back the badges when holding none of them would let someone learn that rows they cannot see were created or deleted.

## The contract version

The JSON a screen serialises to follows a versioned contract, whose JSON Schema lives with the renderer. `Rollogi\NuxtUi\Support\UiSchema::VERSION` is the version the installed package builds to; 1.0.0 builds to **1.34**.

Every manifest and screen reports it as `uiVersion`. The renderer compares it with its own: it warns on a minor mismatch and refuses a major one.

Leave `schema_version` unset in normal use. Set `NUXT_UI_SCHEMA_VERSION` only to pin a renderer that is behind the package, while you upgrade it. The override changes only the reported number, not the trees, so check that the screens you serve use nothing the older renderer lacks.

## Scoping abilities to a resource

Every `can` condition is folded through `UiContext::can()`, which asks `$user->can($permission)`. To answer for the resource a screen is about, such as a project named by `?params[id]=...`, subclass `UiContext` (it is a `readonly` class) and rebind `BuildUiContextAction` to construct it:

```php [app/Modules/Projects/Ui/ProjectUiContext.php]
use Override;
use Rollogi\NuxtUi\Support\UiContext;

readonly class ProjectUiContext extends UiContext
{
    #[Override]
    public function can(string $permission): bool
    {
        $projectId = $this->params['id'] ?? null;

        return $projectId === null
            ? parent::can($permission)
            : $this->user->can($permission, Project::query()->findOrFail($projectId));
    }
}
```

```php [app/Modules/Projects/Ui/BuildProjectUiContextAction.php]
use Illuminate\Contracts\Auth\Access\Authorizable;
use Override;
use Rollogi\NuxtUi\Actions\BuildUiContextAction;
use Rollogi\NuxtUi\Actions\ResolveUiDiscriminatorsAction;
use Rollogi\NuxtUi\Actions\ResolveUiParamsAction;
use Rollogi\NuxtUi\Contracts\UiDefinition;
use Rollogi\NuxtUi\Support\UiContext;

class BuildProjectUiContextAction extends BuildUiContextAction
{
    #[Override]
    public function __invoke(UiDefinition $definition, Authorizable $user, string $tenantId, array $query): UiContext
    {
        return new ProjectUiContext(
            user: $user,
            tenantId: $tenantId,
            discriminators: ResolveUiDiscriminatorsAction::run($definition, $query),
            params: ResolveUiParamsAction::run($query),
        );
    }
}

// in a provider's register()
$this->app->bind(BuildUiContextAction::class, BuildProjectUiContextAction::class);
```

The check behind a screen's `requires()` (and a nav item's) asks `$user->can()` directly rather than the context, so keep `requires()` to abilities the viewer holds in the tenant.

## Rebinding actions

Every action in the package is resolved from the container through `SomeAction::run()`, so a host rebinds one to change it. The ones you are most likely to reach for:

| Action | Decides |
| --- | --- |
| `BuildUiContextAction` | The `UiContext` a screen builds with |
| `IsTenantFreeManifestAction` | Whether a manifest is served with no tenant (by default: the caller names none and belongs to none) |
| `CanWatchTeamNavAction` | Whether a member may listen on the nav channel |

## Versioning

The package follows Semantic Versioning on its own, apart from the kit and `rollogi/core`. Its UI contract version is a separate number, `UiSchema::VERSION`; the [changelog](/nuxt-ui/changelog) records the contract version a release builds to.
