`rollogi/nuxt-ui` follows [Semantic Versioning](https://semver.org/) and is versioned on its own, apart from the starter kit and `rollogi/core`. This page mirrors the package's `CHANGELOG.md`. See [Package releases](/releases/packages) for how a version is tagged and published.

## 1.0.0 - 2026-10-26

The first release. Requires PHP 8.5, `laravel/framework` `^13.32`, `rollogi/core` `^1.1`,
`spatie/laravel-data` `^4.23` and `spatie/laravel-query-builder` `^7.3.2`.

### Added

- The server-driven UI on `rollogi/core`, at UI
  contract `1.34`: the builder (`Rollogi\NuxtUi\Builder`), `UiRegistry` for pages, shells,
  overlays and nav items, the `/api/ui/routes`, `/api/ui/nav`, `/api/ui/pages/{name}` and
  `/api/ui/overlays/{name}` endpoints, `TenantFree` screens, nav badges with `NavBadgeResolver`,
  after-commit nav announcements on `private-teams.{tenantId}.nav`, server-side tables through
  `ApplyListQueryAction` and `ResolvedCursorPaginator`, and `Testing\TableAssertions`.
- `config/nuxt-ui.php` with `schema_version`, `tenant_middleware` and `nav_channel_abilities`.
- `nuxt-ui.tenant_middleware`, run after the tenant is resolved on every tenant request (the kit's
  `EnsureTwoFactorSatisfied` by default where it exists), so a tenant that requires two-factor
  answers `403 two-factor-required` on `/api/ui/*` as on its other routes.
- `NavBadgeContext` (user and nullable tenant id), which `NavBadgeResolver::__invoke()` takes, so
  the contract can grow without breaking resolvers and a no-tenant manifest says so.
- `UiSchema::VERSION`, the contract version the package builds to; `schema_version`
  (`NUXT_UI_SCHEMA_VERSION`) now only overrides it.
- `Table::leftJoin()`, for a nullable foreign key, so a row with no match stays in the list.
- Table search on MySQL and MariaDB (`LIKE` with a backslash escape they read correctly).
- PHPStan's missing-`#[Override]` check over the package.

### Fixed

- `OptionsFilter` matches options named `true` or `false`, which the query string reads as
  booleans.
- `Form::fromData()` makes an `Optional` property optional and binds the name the Data class reads
  from input (`#[MapInputName]`, `#[MapName]`).


### Changed from the module it was extracted from

- The user is typed as `Illuminate\Contracts\Auth\Access\Authorizable` rather than an application
  model, and `NavBadgeResolver` takes a `NavBadgeContext` rather than a user and a tenant id.
- The services extend Core's `ReadService` (authorise, log, metric) rather than a hand-written
  `LogServiceCall` list.
- Server-scoped screens, dashboards and the platform home are not part of the package; a host
  scopes abilities by subclassing `UiContext`.
- A manifest is served with no tenant to someone who names none and belongs to none, rather than by
  platform abilities and tenant suspension; nav items opt in with `NavItem::$tenantFree` rather than
  by a `platform.` ability prefix. The nav channel admits every member of the active tenant unless
  `nav_channel_abilities` lists some.
- `TeamNavChanged` is a queued broadcast (`ShouldBroadcast`) carrying `everyTenant` for a global
  change, whose tenant ids the worker reads, rather than broadcasting to every tenant before the
  response.
- `ShowUiPageData` and `ShowUiOverlayData` lose `tenantFree`, which only the server-scope check read.
