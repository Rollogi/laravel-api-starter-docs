The Laravel API Starter is an API-only, modular, single-database multi-tenant SaaS starter kit for Laravel 13 on PHP 8.5. There is no frontend, no session and no Vite: it is a foundation for tenant-scoped REST APIs, authenticated with Passport OAuth on the `auth:api` guard.

It is distributed as a Laravel project skeleton, so a new API starts with one command:

```bash [Terminal]
laravel new my-api --using=rollogi/laravel-api-starter
```

From then on the project is yours. The kit's later improvements arrive through two channels: `composer update rollogi/core` for the shared infrastructure, and a git merge from upstream for everything else (see [Staying in sync](/getting-started/upstream-sync)).

## What you get

- **Multi-tenancy in one database.** Tenant data carries a `tenant_id` and the `BelongsToTenant` trait scopes every query to the tenant resolved from the `X-Tenant` header. Users are global and belong to many tenants, with roles per tenant. See [Multi-tenancy](/kit/multi-tenancy).
- **One shape for every use case.** A request flows Data, invokable Controller, Service, Action, Policy. Each service runs its work through a pipeline of stages that authorise, log, replay idempotent calls, audit, emit metrics, invalidate cache tags, index for search and wrap the call in a transaction. See [Use cases](/kit/use-cases) and [Service pipeline](/core/service-pipeline).
- **Account security.** Password, magic link, passkey (WebAuthn) and social sign-in (Google, GitHub, Microsoft, Apple), TOTP two-factor that a tenant can make mandatory, session management and recorded login attempts. See [Authentication](/kit/authentication).
- **HTTP conventions.** RFC 9457 problem responses, cursor pagination, sorting and filtering, ETags, rate limiting, fail-closed edge caching, versioning and deprecation headers. See [HTTP conventions](/kit/http).
- **Operations.** Feature toggles per tenant, audit trails with retention, a token-protected health report, a production image on the Rollogi PHP images, and Octane support. See [Feature toggles](/kit/feature-toggles), [Auditing](/kit/auditing) and [Deployment](/kit/deployment).
- **Scaffolding.** `php artisan make:module` and `php artisan make:use-case` write a module or a whole use-case slice in the shape the kit's layering test enforces.

## Shipped modules

Feature code lives in self-contained modules under `app/Modules/<Name>/`, each discovered from its `<Name>ServiceProvider` with no registry to edit. The kit ships five:

| Module | What it does |
| --- | --- |
| `Account` | Self-service on the caller's own account: rename, re-verified email change, deletion with a last-admin guard, a queued JSON export. See [Account](/kit/account). |
| `Auth` | Registration, sign-in, two-factor, passkeys, magic links, social sign-in, sessions and password changes. See [Authentication](/kit/authentication). |
| `Notifications` | Firebase push devices, per-user preferences and an in-app inbox. See [Notifications](/kit/notifications). |
| `Tenants` | A tenant and the people in it: lifecycle, settings, members, invitations, roles and permissions, the activity stream and tenant API keys. See [Tenants](/kit/tenants). |
| `Webhooks` | Outbound webhooks: per-tenant subscriptions, signed deliveries with retries, a delivery log and replay. See [Webhooks](/kit/webhooks). |

Add your own next to them with `php artisan make:module Projects`. Keeping your code in `app/Modules/` is also what keeps upstream merges quiet.

## The packages

Three Composer packages are developed inside the kit's repository and published to their own private repositories:

::card-group
  :::card
  ---
  icon: i-lucide-boxes
  title: rollogi/core
  to: /core
  ---
  The shared infrastructure every project installs: the service pipeline, actions, tenancy, features, HTTP conventions, auditing, authorisation, integrations, health and the generators. No business logic.
  :::

  :::card
  ---
  icon: i-lucide-credit-card
  title: rollogi/billing
  to: /billing
  ---
  Optional Stripe billing on Laravel Cashier: plans, subscriptions, seats, metered usage and plan-gated features, for a tenant or a person.
  :::

  :::card
  ---
  icon: i-lucide-layout-dashboard
  title: rollogi/nuxt-ui
  to: /nuxt-ui
  ---
  Optional server-driven UI: screens built in PHP and served as JSON trees for a Nuxt UI renderer.
  :::
::

The kit requires `rollogi/core` and nothing else. Billing and nuxt-ui are package modules that a project adds when it wants them.

## Requirements

- PHP 8.5 or later
- Composer
- SQLite (the default), MySQL 8 or later, or PostgreSQL 15 or later
- A GitHub token that can read the private `Rollogi/*` repositories you install from
- Docker, only to run the test suite against MySQL and PostgreSQL locally, or to use the development container

The kit is built on Laravel 13 (`laravel/framework` `^13.32`), and the suite runs on SQLite, MySQL 8.4 and PostgreSQL 17 in CI.

::note
The kit and its packages live in private repositories. Installing a project, or adding billing or nuxt-ui to one, needs access to the matching `Rollogi/*` repository. [Installation](/getting-started/installation) shows how to give Composer a token.
::
