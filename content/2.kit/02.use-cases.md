Every request in the kit flows the same way: **Data → invokable Controller → Service → Action → Policy**. The separation is what gives every write the same audit row, transaction boundary, metric and authorisation check without the use-case writing any of it.

| Layer | Role |
|---|---|
| **Data** | Shape and validation for input and output (`spatie/laravel-data`). Implements `AuthorizesService` when the use-case needs authorising |
| **Controller** | Single-action invokable. Injects or builds the Data, calls `SomeService::run($data)`, returns a `JsonResponse` |
| **Service** | Orchestrates the use-case through a pipeline of stages, then runs actions. Holds no reusable logic |
| **Action** | One reusable operation. This is where the work lives |
| **Policy** | Who may do it, per tenant, registered with `Gate::policy()` in the module provider |

**Services orchestrate; actions execute.** If a service contains logic that something else could reuse, extract it to an action. `ModuleLayeringTest` checks that every controller delegates to a service, that no controller writes to Eloquent, that every service runs actions, and that a Data class declaring `authorizeService()` implements the contract.

## Adding a module

```bash
php artisan make:module Billing
```

That writes the provider, a routes file with a `/api/billing/ping` smoke route, an empty migrations directory and a smoke test:

```text
app/Modules/Billing/
├── Database/Migrations/.gitkeep
├── routes/api.php
└── BillingServiceProvider.php
tests/Feature/Billing/BillingModuleTest.php
```

`ModuleServiceProvider` picks the module up on the next boot. The command refuses to run if the directory already exists.

## Adding a use-case

```bash
php artisan make:use-case Billing CreateInvoice --uri=/invoices           # POST  /api/billing/invoices
php artisan make:use-case Billing ListInvoices --read --uri=/invoices     # GET   /api/billing/invoices
php artisan make:use-case Billing ArchiveInvoice --method=patch           # PATCH /api/billing/archive-invoice
```

| Option | Default | Meaning |
|---|---|---|
| `module` | | The module, which must already have a `routes/api.php` |
| `name` | | The use-case in StudlyCase, verb first |
| `--read` | off | A use-case that persists nothing: a `ReadService`, a `GET` route, and a Data built in the controller from `tenancy()->id()` |
| `--method=` | `post` (`get` with `--read`) | One of `get`, `post`, `put`, `patch`, `delete` |
| `--uri=` | `/<use-case-kebab>` | Path under `/api/<module-kebab>` |

One command writes the whole vertical slice and wires it up:

| File | What it is |
|---|---|
| `Data/CreateInvoiceData.php` | Request shape with validation attributes, implementing `AuthorizesService` |
| `Data/CreateInvoiceResultData.php` | The response shape the service returns |
| `Actions/CreateInvoiceAction.php` | The operation, with a typed `__invoke()` |
| `Services/CreateInvoiceService.php` | `@extends Service<CreateInvoiceData, CreateInvoiceResultData>` and a `handle()` that runs the action |
| `Http/Controllers/CreateInvoiceController.php` | Invokable; injects the Data, calls the service, answers `201` for a `POST` and `200` otherwise |
| `routes/api.php` | A group under `api.tenant` and `feature:billing.create_invoice`, with the import kept in order |
| `config/features.php` | The `billing.create_invoice` feature key, enabled by default |
| `tests/Feature/Billing/CreateInvoiceTest.php` | Pest tests: the happy path, `403` without the permission, `422` on an invalid payload (write shape only), `401` unauthenticated |

The generated `authorizeService()` calls `Gate::authorize('billing.create_invoice')`, a permission named after the feature key, which spatie/laravel-permission resolves per tenant. Grant it in `RolesAndPermissionsSeeder`, or replace the call with a policy check once the module has a model. The `name` field in both Data classes is a placeholder.

::note
The generator never overwrites anything. If any target file exists, nothing is written and the command lists the files in the way.
::

## The slice, layer by layer

### 1. Data

```php [app/Modules/Billing/Data/CreateInvoiceData.php]
class CreateInvoiceData extends Data implements AuthorizesService
{
    public function __construct(
        #[Required, Min(1)]
        public readonly int $amount,
    ) {}

    public function authorizeService(): void
    {
        Gate::authorize('create', Invoice::class);
    }
}
```

The `AuthorizeAction` stage calls `authorizeService()` before the service does any work. A Data class with the method but without the `Rollogi\Core\Services\Contracts\AuthorizesService` interface is refused with a `LogicException`, so a forgotten `implements` cannot silently skip the check.

::warning
A property with a default value has its validation rules skipped when it is absent from the payload. An either-or pair (`RequiredWithout`) must therefore have no defaults; `TwoFactorChallengeAttemptData` in the Auth module is the example.
::

### 2. Controller

```php [app/Modules/Billing/Http/Controllers/CreateInvoiceController.php]
class CreateInvoiceController
{
    #[Response(status: 422, description: 'Validation failed.')]
    public function __invoke(CreateInvoiceData $data): JsonResponse
    {
        return new JsonResponse(CreateInvoiceService::run($data), Response::HTTP_CREATED);
    }
}
```

Scramble infers the request body from the injected Data class, but only infers `422` responses from FormRequests, so add the `Dedoc\Scramble\Attributes\Response` attribute yourself. For a read, build the Data in the controller instead (pagination, sort and filter come off the request, the tenant from `tenancy()->id()`), so the use-case stays callable from a job or command.

### 3. Service

```php [app/Modules/Billing/Services/CreateInvoiceService.php]
/**
 * @extends Service<CreateInvoiceData, InvoiceData>
 */
class CreateInvoiceService extends Service
{
    protected function handle(mixed $input): mixed
    {
        return CreateInvoiceAction::run($input);
    }
}
```

A service inherits the write preset of stages (authorise, log, idempotent replay, audit, metric, cache tags, search index, transaction). A read extends `ReadService` (authorise, log, metric). A write that must not run in a transaction drops that one stage with `$this->stagesWithout(WrapInTransaction::class)` and says why in a comment. The generic annotation types `handle()`'s parameter and `run()`'s return, so `handle()` never opens with an `assert()`. The stages, idempotency keys, lifecycle events and adding your own are covered in [Service pipeline](/core/service-pipeline).

### 4. Action

```php [app/Modules/Billing/Actions/CreateInvoiceAction.php]
class CreateInvoiceAction extends Action
{
    public function __invoke(CreateInvoiceData $data): InvoiceData
    {
        $invoice = Invoice::query()->create(['amount' => $data->amount]);

        return InvoiceData::fromModel($invoice);
    }
}
```

`SomeAction::run()` returns `__invoke()`'s type, and its arguments are checked against `__invoke()` by Core's PHPStan extensions ([Static analysis](/core/static-analysis)). Actions and services can also be queued, chained, batched, used as event listeners or faked in tests: see [Actions](/core/actions).

### 5. Policy

```php [app/Modules/Billing/Policies/InvoicePolicy.php]
class InvoicePolicy
{
    public function create(User $user): bool
    {
        return $user->can('invoices.create');
    }
}
```

Register it in the module provider with `Gate::policy(Invoice::class, InvoicePolicy::class)`. Permissions are resolved in the active tenant, because Spatie's team id is the tenant id ([Multi-tenancy](/kit/multi-tenancy)).

### 6. Route

```php [app/Modules/Billing/routes/api.php]
Route::middleware(['api.tenant', 'feature:billing.create_invoice'])->prefix('api/billing')->group(function (): void {
    Route::post('/invoices', CreateInvoiceController::class);
});
```

Every authenticated resource route sits behind `api.tenant`, and every capability has a [feature key](/kit/feature-toggles).

## Responses

Controllers answer with `new JsonResponse($data, Response::HTTP_*)`, never a bare integer. Errors are thrown, not returned: validation failures, denied policies and `ProblemException`s all become RFC 9457 problem documents ([HTTP conventions](/kit/http)).
