A tenant subscribes an endpoint of its own to the events the kit announces, and the `Webhooks` module delivers them signed, retries on failure, keeps a log and can replay. It mirrors Core's inbound receiver: the same `X-Signature` HMAC and the same `event_id` / `type` envelope keys, so one kit can receive another kit's webhooks with the stock handler. Receiving webhooks from third parties is covered in [Integrations](/core/integrations).

## Subscriptions

Every route requires `api.tenant`, `feature:webhooks.outbound` and the `webhooks.manage` permission (seeded on `admin`, since a subscription sends the tenant's data to an address of the caller's choosing).

| Method | Path | Effect |
|---|---|---|
| `GET` | `/api/webhooks/events` | The subscribable events from `config/webhooks.php`, each with a label |
| `GET` | `/api/webhooks/subscriptions` | The tenant's subscriptions: `id`, `url`, `events`, `description`, `active`, `createdAt`, never the secret |
| `POST` | `/api/webhooks/subscriptions` | `url`, `events[]` (registered names, or `"*"` for all), `description?`; `201` with `{ subscription, secret }`, the only time the secret is shown |
| `PATCH` | `/api/webhooks/subscriptions/{id}` | Any of `url`, `events`, `description`, `active`; `active: false` pauses delivery without losing the log |
| `POST` | `/api/webhooks/subscriptions/{id}/secret` | Rotates the secret and returns the new one once; deliveries already queued sign with it |
| `DELETE` | `/api/webhooks/subscriptions/{id}` | Removes the subscription and its log; a delivery still queued is dropped when it runs |
| `GET` | `/api/webhooks/subscriptions/{id}/deliveries` | The delivery log, newest first, cursor-paginated; `?filter[status]=failed` and `?filter[event]=...` |
| `POST` | `/api/webhooks/deliveries/{id}/replay` | Queues the same event and payload again as a new delivery linked to the original; `202` |

A URL must be `https` and must not name localhost, a private or a loopback address. `WEBHOOK_ALLOW_INSECURE_URLS=true` lifts the `https` rule for local work. An unknown event or a disallowed URL is a `422`. Redirects are never followed, so a public endpoint cannot bounce a delivery to a private one.

## What is delivered

Each delivery is a `POST` to the subscription URL:

```http
POST /hooks/kit HTTP/1.1
Content-Type: application/json
X-Signature: <hex HMAC-SHA256 of the raw body with the subscription secret>
X-Webhook-Id: 01a1...
X-Webhook-Event: tenant.member.role_changed
X-Webhook-Attempt: 1

{
  "event_id": "01a1...",
  "type": "tenant.member.role_changed",
  "occurred_at": "2026-10-22T09:00:00+00:00",
  "tenant_id": "...",
  "data": { "member": { "id": "...", "name": "...", "email": "..." }, "role": "admin" }
}
```

`X-Webhook-Id` is the delivery id, which is also `event_id` in the body. A replay adds `replay_of` with the original delivery's id. The signature header name comes from Core's `integrations.webhooks.signature_header` (`WEBHOOK_SIGNATURE_HEADER`, default `X-Signature`).

### Verifying on the receiving side

Recompute the HMAC over the **raw** body and compare in constant time; deduplicate on `event_id`, which is a UUIDv7 and so also orders deliveries.

```php
$expected = hash_hmac('sha256', $request->getContent(), $secret);

abort_unless(hash_equals($expected, (string) $request->header('X-Signature')), 401);
```

## Events the kit publishes

The `PublishDomainEvents` listener turns the Tenants module's domain events into webhooks:

| Event | Raised from | `data` |
|---|---|---|
| `tenant.invitation.created` | `InvitationCreated` | `invitation: { id, email, role, expiresAt }`, never the token |
| `tenant.member.joined` | `MemberJoined` | `member: { id, name, email }`, `role` |
| `tenant.member.role_changed` | `MemberRoleChanged` | `member`, `role` |
| `tenant.member.removed` | `MemberRemoved` | `member`, `left` (true when the person left, false when removed) |
| `tenant.updated` | `TenantUpdated` | `tenant: { id, name }` |

## Delivery, retries and replay

`PublishWebhookEventAction::run($event, $data)` fans an event out to every active subscription of the active tenant (or of a tenant id passed as the third argument) that wants it: one `webhook_deliveries` row and one queued `DeliverWebhook` job per subscription, dispatched after the surrounding transaction commits.

`DeliverWebhook` extends Core's `SendIntegrationRequest`, so it runs under the tenant's execution context and is audited like any outbound call. A non-2xx answer or a connection failure records the attempt and throws; the queue retries on `webhooks.backoff` (30 seconds, 2 minutes, 10 minutes, 1 hour; the last repeats) up to `WEBHOOK_MAX_ATTEMPTS`, and the delivery is then marked `failed` with the last error. A delivery's status is `pending`, `delivered` or `failed`.

Replay from the API or the console:

```bash
php artisan webhook:replay <delivery-id>            # one delivery
php artisan webhook:replay --failed                 # every failed delivery
php artisan webhook:replay --failed --tenant=<id>   # one tenant's
```

A replay is a new delivery with a new `event_id`, linked to the original, so the log keeps every attempt.

## Publishing an event of your own

1. Register the name and a label in `config/webhooks.php`:

   ```php [config/webhooks.php]
   'events' => [
       // ...
       'billing.invoice.paid' => 'An invoice was paid',
   ],
   ```

2. Call the action from a listener on your module's domain event, building the payload by hand so a webhook never carries more than it should:

   ```php [app/Modules/Billing/Listeners/PublishInvoicePaid.php]
   class PublishInvoicePaid
   {
       public function handle(InvoicePaid $event): void
       {
           PublishWebhookEventAction::run('billing.invoice.paid', [
               'invoice' => ['id' => $event->invoice->getKey(), 'number' => $event->invoice->getAttribute('number')],
           ]);
       }
   }
   ```

An unregistered name throws an `InvalidArgumentException`, so a typo cannot silently publish nothing. The `PublishDomainEvents` listener is the pattern to follow.

## Testing

Test deliveries with Saloon's `MockClient` against `WebhookRequest`, and dispatches with `Bus::fake([DeliverWebhook::class])`.

## Configuration

| Env | Config key | Default | Meaning |
|---|---|---|---|
| | `webhooks.events` | the five `tenant.*` events | The events a tenant may subscribe to |
| `WEBHOOK_TIMEOUT` | `webhooks.timeout` | `10` | Seconds a delivery waits for the endpoint |
| `WEBHOOK_MAX_ATTEMPTS` | `webhooks.max_attempts` | `5` | Attempts before a delivery is marked failed |
| | `webhooks.backoff` | `[30, 120, 600, 3600]` | Seconds between attempts |
| `WEBHOOK_DELIVERY_RETENTION_DAYS` | `webhooks.delivery_retention_days` | `30` | Days a delivery stays in the log |
| `WEBHOOK_ALLOW_INSECURE_URLS` | `webhooks.allow_insecure_urls` | `false` | Allow plain `http` subscription URLs (local development only) |
| `WEBHOOK_SIGNATURE_HEADER` | `integrations.webhooks.signature_header` | `X-Signature` | Header carrying the HMAC (Core config, shared with inbound webhooks) |
