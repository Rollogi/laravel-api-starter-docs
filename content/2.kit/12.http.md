Every endpoint follows the same conventions, so a client written against one module works against the next. Most are implemented by middleware from rollogi/core composed into the `api` group in `bootstrap/app.php`:

| Position | Middleware | Does |
|---|---|---|
| prepended | `RequestId` | Reads or issues `X-Request-Id` and echoes it on the response |
| prepended | `SecurityHeaders` | The security headers below, even on a `401` |
| prepended | `IdempotencyKey` | Reads `Idempotency-Key` into the request-scoped context |
| prepended | `SetRequestLocale` | Picks the locale from `Accept-Language` |
| prepended | `ReportApiVersion` | Adds `API-Version` |
| appended | `throttle:api` | The per-user rate limit ([Rate limiting and caching](/kit/rate-limiting-and-caching)) |
| appended | `SetDefaultCacheControl` | `Cache-Control: private, no-store` unless a route opted in to public caching |
| appended | `AddEntityTag` | `ETag` and `304` on successful `GET` and `HEAD` |

## Errors (RFC 9457)

Every exception on an `api/*` request, or on any request that expects JSON, is rendered by `Rollogi\Core\Http\Problems\ProblemDetailsRenderer` as one `application/problem+json` document:

```json
{
  "type": "https://api.example.com/problems/validation-failed",
  "title": "Validation failed",
  "status": 422,
  "detail": "The email field is required. (and 1 more error)",
  "instance": "/api/auth/login",
  "request_id": "0192b1c2-...",
  "errors": { "email": ["The email field is required."], "password": ["The password field is required."] }
}
```

| Member | Value |
|---|---|
| `type` | A stable URI per kind of error: `PROBLEM_TYPE_BASE` (default `APP_URL/problems`) plus a slug |
| `title` | Short, fixed per type |
| `status` | The HTTP status, repeated in the body |
| `detail` | The human-readable message for this occurrence |
| `instance` | The request path |
| `request_id` | The `X-Request-Id` the request carried or was given |
| extensions | `errors` on `validation-failed`, `retry_after` (seconds) on `too-many-requests`, `feature` on `feature-disabled` |

There is no `message` key. Clients should branch on `type`, not on `detail`.

### Problem types

| Type | Status | When |
|---|---|---|
| `validation-failed` | 422 | Validation failed; `errors` lists the fields |
| `unauthenticated` | 401 | No or invalid bearer token |
| `forbidden` | 403 | A policy or permission check failed |
| `not-found` | 404 | No such route or record |
| `too-many-requests` | 429 | A rate limit, including Saloon's `RateLimitReachedException`; with `Retry-After` |
| `feature-disabled` | 403 | The route's feature toggle is off |
| `tenant-required` | 400 | No `X-Tenant` and the user has zero or several memberships |
| `tenant-forbidden` | 403 | Not a member of the named tenant |
| `tenant-suspended` | 403 | The tenant is suspended |
| `tenant-not-found` | 404 | A tenant id that does not exist |
| `two-factor-required` | 403 | The tenant requires two-factor and the member has none |
| `machine-forbidden` | 403 | A tenant API key on an account-level route |
| `email-change-expired` | 410 | A used or superseded email change link |
| `idempotency-key-invalid` | 400 | An empty, overlong or non-ASCII `Idempotency-Key` |
| `idempotency-key-reused` | 422 | The same key with a different payload |
| `idempotency-conflict` | 409 | The first call under the key is still running |
| `health-forbidden` | 403 | `GET /api/health` without a matching token |
| `internal-server-error` | 500 | Anything unexpected; quotes the request id, never the exception message |

Any other HTTP exception is named after its status text (`method-not-allowed`, `conflict`, ...).

To raise a problem of your own, throw `ProblemException` with a status, a type slug, a title and a detail:

```php
use Rollogi\Core\Http\Problems\ProblemException;
use Symfony\Component\HttpFoundation\Response;

throw new ProblemException(Response::HTTP_CONFLICT, 'invoice-already-paid', 'Invoice already paid', 'Invoice INV-42 was paid on 3 March.');
```

Two cases are left to the framework on purpose: a request outside `/api` that does not ask for JSON gets Laravel's HTML page, and an unexpected exception while `APP_DEBUG` is on gets Laravel's JSON with the stack trace.

## Pagination

List endpoints are cursor-paginated. `Rollogi\Core\Http\Data\PaginationData` reads `per_page` and `cursor` off the query string and is composed into the read Data object, so the use-case stays callable from a job or a command.

```http
GET /api/tenants/current/members?per_page=25
GET /api/tenants/current/members?per_page=25&cursor=eyJ1c2Vyc19pZCI6...
```

```json
{
  "data": [{ "id": "...", "name": "...", "email": "...", "kind": "person", "roles": ["admin"], "joinedAt": "..." }],
  "meta": { "per_page": 25, "next_cursor": "eyJ1c2Vy...", "prev_cursor": null, "path": "..." }
}
```

Cursor rather than offset, and cheaply so: UUIDv7 keys sort by creation time, so ordering on `id` is stable and chronological, and rows are never skipped or repeated when records are inserted mid-traversal. `per_page` defaults to `PAGINATION_PER_PAGE` (25) and is clamped to `PAGINATION_PER_PAGE_MAX` (100), so `?per_page=100000` cannot restore an unbounded query.

To paginate a new list, follow `ListTenantMembersAction`: order by a stable column, call `cursorPaginate()` with the values off `PaginationData` (`PaginationData::cursorName()` for the cursor name), and collect into `SomeData::collect($paginator, CursorPaginatedDataCollection::class)`. Paginated collections are always wrapped in `data`.

## Filtering and sorting

```http
GET /api/tenants/current/members?sort=-name                  # a leading minus is descending; comma-separate several fields
GET /api/tenants/current/members?filter[role]=admin,user     # a comma separates alternatives
GET /api/tenants/current/members?filter[kind]=machine&sort=email
```

`SortData` and `FilterData` parse the query string against an allow-list and sit in the read Data beside `PaginationData`. The controller builds them, so the allow-list lives on the use-case:

```php [app/Modules/Tenants/Http/Controllers/ListMembersController.php]
$data = new ListMembersData(
    tenantId: (string) tenancy()->id(),
    pagination: PaginationData::fromRequest($request),
    sort: SortData::fromRequest($request, ListMembersData::SORTABLE),
    filter: FilterData::fromRequest($request, ListMembersData::FILTERABLE),
);
```

The action applies them. A sort maps fields to columns; a filter key without an applier is a plain `whereIn`:

```php [app/Modules/Tenants/Actions/ListTenantMembersAction.php]
$filter->apply($query, [
    'role' => function (BelongsToMany $members, array $values): void {
        $members->role($values);
    },
]);
$sort->apply($query, ['name' => 'users.name', 'email' => 'users.email']);

$query->orderBy('users.id')->cursorPaginate(/* ... */);
```

A field or key outside the allow-list is a `422` on `sort` or `filter.<key>`. Always order by `id` after the requested sort so the cursor has a unique column, and only make a field sortable if it is present on the returned Data, because the cursor is read off the last item.

## Conditional requests

Every successful `GET` or `HEAD` carries an `ETag` (a SHA-1 of the body), and a request that sends it back as `If-None-Match` gets a bodiless `304 Not Modified`. The default `Cache-Control` stays `private, no-store`, so this is for clients that keep the tag themselves, such as a mobile app refreshing a list on resume. Writes and errors are never tagged.

## Versioning and deprecation

The API evolves additively: fields and endpoints are added, nothing is removed or renamed in place. Every response reports `API-Version: <date>` from `API_VERSION` (Core's `api.version`), so a client can tell which contract it got.

When something must go, the old route stays for a sunset period and carries the `deprecated` middleware, which adds `Deprecation` (RFC 9745), `Sunset` (RFC 8594) and an optional `Link; rel="deprecation"`:

```php
Route::get('/members', ListMembersV1Controller::class)
    ->middleware('deprecated:2026-10-22,2027-04-22,https://developers.example.com/changes#members');
```

A breaking change that cannot be made additively gets a new path (`/api/v2/<module>/...`, registered by the module beside the old one) rather than a version header, so both versions are plain routes with plain tests. There is no `v1` prefix today on purpose: the unversioned path is the current contract.

## Locale

`Accept-Language` picks the request's locale from `API_LOCALES` (comma-separated, default `en`), and validation messages come back in it. The response names it in `Content-Language` and varies on `Accept-Language`. Anything outside the list falls back to `app.locale`. To add a language, publish the framework's lines (`php artisan lang:publish`), translate `lang/<locale>/validation.php`, and add the locale to `API_LOCALES`.

## Idempotency keys

A client that may retry a write sends `Idempotency-Key: <uuid>`. The first call runs and its result is stored; a repeat with the same input gets the stored result with `Idempotency-Replayed: true`, and nothing runs twice. Reads and queued services are not covered. The rules and the three problem types are described in [Service pipeline](/core/service-pipeline).

## Security headers, CORS, proxies and HTTPS

- **`SecurityHeaders`** sends `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`, plus `Strict-Transport-Security` (`HSTS_MAX_AGE`, default a year) on a request that was actually secure. It is prepended because the priority list moves `auth:api` ahead of `throttle:api`, so an appended middleware would never see a `401`.
- **CORS** (`config/cors.php`) allows `CORS_ALLOWED_ORIGINS` (comma-separated), defaulting to `FRONTEND_URL`, never `*`. It exposes `X-Request-Id` and `Retry-After` and caches preflights for an hour.
- **Trusted proxies** (`config/trustedproxy.php`): `TRUSTED_PROXIES` is a comma-separated list of IPs or CIDRs, or `*` when the app is reachable only through its load balancer. Nothing is trusted by default. Behind a proxy it must be set, or the rate limiters key on the proxy's address and every request looks like plain HTTP.
- **HTTPS**: `FORCE_HTTPS=true` makes every generated URL use `https`.

## Configuration

| Env | Config key | Default | Meaning |
|---|---|---|---|
| `PROBLEM_TYPE_BASE` | `problems.type_base` | `APP_URL/problems` | Base of every problem `type` URI |
| `PAGINATION_PER_PAGE` | `pagination.per_page.default` | `25` | Page size when `per_page` is absent |
| `PAGINATION_PER_PAGE_MAX` | `pagination.per_page.max` | `100` | Largest page a client may ask for |
| `API_VERSION` | `api.version` | `2026-10-22` | Reported in `API-Version` |
| `API_LOCALES` | `api.locales` | `en` | Locales `Accept-Language` may select |
| `IDEMPOTENCY_HEADER` | `idempotency.header` | `Idempotency-Key` | Header carrying the key |
| `IDEMPOTENCY_TTL_MINUTES` | `idempotency.ttl_minutes` | `1440` | How long a result can be replayed |
| `IDEMPOTENCY_LOCK_SECONDS` | `idempotency.lock_seconds` | `30` | Lock held while the first call runs |
| `FORCE_HTTPS` | `http.force_https` | `false` | Generate `https` URLs |
| `HSTS_MAX_AGE` | `http.hsts_max_age` | `31536000` | `Strict-Transport-Security` max-age |
| `CORS_ALLOWED_ORIGINS` | `cors.allowed_origins` | `FRONTEND_URL` | Origins allowed by CORS |
| `TRUSTED_PROXIES` | `trustedproxy.proxies` | none | Proxies whose forwarded headers are trusted |

The `problems`, `pagination`, `api`, `idempotency` and `http` keys are Core config, merged in as defaults; publish them with `php artisan vendor:publish --tag=rollogi-core-config` to change more than the env variables allow.
