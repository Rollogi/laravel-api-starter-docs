Two stages in the write preset send data to pluggable sinks: `EmitMetric` to a metrics backend and `IndexForSearch` to a search index. Both sinks default to a `null` driver that discards everything, so a fresh project pays nothing until it plugs a backend in.

## Metrics

`Rollogi\Core\Metrics\Contracts\Metrics` is the sink:

```php
interface Metrics
{
    public function increment(string $metric, int $by = 1, array $tags = []): void;

    public function gauge(string $metric, float $value, array $tags = []): void;

    public function timing(string $metric, float $milliseconds, array $tags = []): void;
}
```

### What the pipeline records

For every service call, `EmitMetric` records:

| Metric | Kind | Tags |
|--------|------|------|
| `service.calls` (`EmitMetric::CALLS`) | Counter, by 1 | `service`, `outcome` (`ok` or `failed`) |
| `service.duration` (`EmitMetric::DURATION`) | Timing, milliseconds | `service`, `outcome` |

The tenant is deliberately not a tag: one series per tenant is a cardinality problem on most backends, and the `service_audits` row carries it. Any action with something worth measuring can inject the same contract.

### Drivers

| `METRICS_DRIVER` | Behaviour |
|------------------|-----------|
| `null` (default) | Discards every measurement |
| `log` | One structured log line per measurement, on `METRICS_LOG_CHANNEL` (null means the default channel) |

Any other value throws an `InvalidArgumentException` naming the contract to bind.

### Your own backend

Core binds the contract with `singletonIf()`, and `AppServiceProvider` registers before Core's providers, so your binding wins:

```php [app/Providers/AppServiceProvider.php]
use Rollogi\Core\Metrics\Contracts\Metrics;

public function register(): void
{
    $this->app->singleton(Metrics::class, StatsdMetrics::class);
}
```

The same applies to StatsD, Prometheus or OpenTelemetry. Leave `METRICS_DRIVER` on `null`; the config only matters when nobody has bound the contract.

## Search

`Rollogi\Core\Search\Contracts\SearchIndexer` is the sink:

```php
interface SearchIndexer
{
    public function index(string $index, string $id, array $document): void;

    public function remove(string $index, string $id): void;
}
```

### Indexing from a use-case

A **result** that implements `IndexesForSearch` is indexed after the write commits:

```php
use Rollogi\Core\Search\Contracts\IndexesForSearch;
use Spatie\LaravelData\Data;

class InvoiceResultData extends Data implements IndexesForSearch
{
    public function __construct(public readonly string $id, public readonly string $reference) {}

    public function searchIndex(): string
    {
        return 'invoices';
    }

    public function searchId(): string
    {
        return $this->id;
    }

    public function searchDocument(): array
    {
        return ['reference' => $this->reference];
    }
}
```

An **input** that implements `RemovesFromSearch` (`searchIndex()`, `searchId()`) has its document removed, which is how a delete use-case clears the index.

`IndexForSearch` queues `IndexSearchDocumentAction` or `RemoveSearchDocumentAction` with `dispatchAfterCommit()`, so a rolled-back write never reaches the index, and the worker runs them under the caller's [execution context](/core/actions#execution-context).

### Drivers

| `SEARCH_DRIVER` | Behaviour |
|-----------------|-----------|
| `null` (default) | Discards every write |
| `log` | Logs each write on `SEARCH_LOG_CHANNEL`, so the documents can be checked before a backend exists |

Bind `SearchIndexer` to your Meilisearch, Typesense or Elasticsearch client in `AppServiceProvider`, exactly as for metrics; the stage needs no change.

## Testing

Both sinks have recording fakes that bind themselves in the container:

```php
use Rollogi\Core\Metrics\Testing\MetricsFake;
use Rollogi\Core\Search\Testing\SearchIndexerFake;

$metrics = MetricsFake::bind();
$search = SearchIndexerFake::bind();

CreateInvoiceService::run($data);

$metrics->assertIncremented('service.calls', fn (int|float $value, array $tags): bool => $tags['outcome'] === 'ok');
$metrics->assertTimed('service.duration');
$search->assertIndexed('invoices', $invoiceId);
```

| Fake | Assertions |
|------|------------|
| `MetricsFake` | `assertIncremented`, `assertTimed`, `assertGauged` (each with an optional callback receiving the value and the tags), `assertNothingRecorded` |
| `SearchIndexerFake` | `assertIndexed($index, $id, ?callback)` (the callback receives the document), `assertRemoved($index, $id)`, `assertNothingIndexed` |

To prove the stage queued the write without running it, fake the bus instead:

```php
Bus::fake();

CreateInvoiceService::run($data);

IndexSearchDocumentAction::assertDispatched();
```

`IndexSearchDocumentAction` and `RemoveSearchDocumentAction` are marked `@internal`; asserting their dispatch in a test is fine, but do not call them from application code.

The fakes assert with PHPUnit, which Core lists under `suggest` rather than `require`.
