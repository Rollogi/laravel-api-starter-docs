Outbound integrations are built on [Saloon v4](https://docs.saloon.dev/). Core provides the base connector, a cacheable request, a queued job base class and an audit of every call; the concrete connector, requests, DTOs and job live in the module that owns the integration. Inbound calls are covered in [Inbound webhooks](/core/inbound-webhooks).

## Connectors

Extend `Rollogi\Core\Integrations\Connector`. It sets `integrations.timeout` on every request and wires Saloon's rate-limit plugin with no limits declared:

```php [app/Modules/Acme/Integrations/AcmeConnector.php]
use Rollogi\Core\Integrations\Connector;

class AcmeConnector extends Connector
{
    public function resolveBaseUrl(): string
    {
        return 'https://api.acme.example';
    }
}
```

Requests are plain Saloon requests; map the response to a Data object with `createDtoFromResponse()` and send inline:

```php
$widget = (new AcmeConnector)->send(new GetWidgetRequest($id))->dto();
```

### Rate limits

Override `resolveLimits()` with the remote API's published limits:

```php
use Saloon\RateLimitPlugin\Limit;

protected function resolveLimits(): array
{
    return [
        Limit::allow(100)->everyMinute(),
        Limit::allow(1000)->everyDay(),
    ];
}
```

Counters live in the cache store named by `integrations.rate_limit.store` (blank means `cache.default`), prefixed with `integrations.rate_limit.prefix` and the connector's class name. Use a shared store such as Redis for limits that hold across servers and workers.

Reactive detection of a server's `429` is opt-in per connector:

```php
protected function getTooManyAttemptsLimiter(): ?Limit
{
    return Limit::custom($this->handleTooManyAttempts(...));
}
```

When a limit is reached on a synchronous `send()`, the `RateLimitReachedException` reaches the problem renderer and becomes `429 too-many-requests` with a `retry_after` member and a `Retry-After` header.

::warning
A limit with `->sleep()` blocks the process for the rest of the window instead of throwing. On a queue worker that can mean hours. Keep `->sleep()` for short windows in synchronous or CLI code.
::

## Queued requests

Extend `Rollogi\Core\Integrations\SendIntegrationRequest` and implement three methods:

```php [app/Modules/Acme/Jobs/SyncWidgetJob.php]
use Rollogi\Core\Integrations\Connector;
use Rollogi\Core\Integrations\SendIntegrationRequest;
use Saloon\Http\Request;
use Saloon\Http\Response;

class SyncWidgetJob extends SendIntegrationRequest
{
    public function __construct(private readonly int $id, ?string $tenantId = null)
    {
        parent::__construct($tenantId);
    }

    protected function connector(): Connector
    {
        return new AcmeConnector;
    }

    protected function request(): Request
    {
        return new GetWidgetRequest($this->id);
    }

    protected function handleResponse(Response $response): void
    {
        // map and store the result
    }
}
```

Pass the tenant id when you dispatch, because a queued job has no request context:

```php
dispatch(new SyncWidgetJob(id: $id, tenantId: tenancy()->id()));
```

The job runs the request inside `ExecutionContext::forTenant($tenantId)`, which restores the tenant and the permission team id and clears them afterwards. A tenant deleted between dispatch and execution leaves the context untouched, so the request still goes out, audited without a tenant.

| Behaviour | Detail |
|-----------|--------|
| Tries | `integrations.retries + 1` (default 3) |
| Back-off | `max(1, retries) * 5` seconds; override `backoff()` for a list |
| Rate limit hit | The job catches `RateLimitReachedException`, logs `integration.rate_limited` with `job` and `retry_after`, and releases itself for the remaining seconds. Each release counts against the tries, so a long-window limit may need more tries or `retryUntil()`. |

::note
Retries engage only on a connection-level failure (Saloon's `FatalRequestException`: timeout, DNS, refused connection). An HTTP error response is handed to `handleResponse()` and audited as `failed`; call `$response->throw()` there if a 4xx or 5xx should be retried.
::

## Response caching

Extend `Rollogi\Core\Integrations\CacheableRequest` instead of `Request` to cache a response through Saloon's cache plugin, in the store named by `integrations.cache.store` (blank means `cache.default`), for `integrations.cache.ttl` seconds. Override `cacheExpiryInSeconds()` on one request for a different lifetime.

`$response->isCached()` tells a hit from a fetch, `$request->invalidateCache()` forces a fresh fetch, and `$request->disableCaching()` skips the cache for one send. A cache hit is still audited, and still counts against a connector's declared limits.

## The integration audit

A global Saloon middleware, registered once per process behind a static guard, writes an `integration_audits` row for every call:

| Column | Holds |
|--------|-------|
| `connector`, `request` | Short class names |
| `method`, `url`, `status` | The HTTP call; `status` is null on a fatal network error |
| `duration_ms` | Round-trip time |
| `state` | `ok` for 2xx and 3xx, `failed` for 4xx, 5xx or an exception |
| `tenant_id`, `actor_id` | From the tenant context and the authenticated user |
| `request_summary`, `response_summary` | Redacted headers, plus the body when enabled |
| `error` | The exception message on a fatal failure |

Each call also logs `integration.<Connector> <status>`. A request stopped by a rate limit before it is sent is logged but not audited. Rows are pruned daily after `INTEGRATION_AUDIT_RETENTION_DAYS`.

## Configuration

`integrations.php`:

| Env | Default | Meaning |
|-----|---------|---------|
| `INTEGRATION_TIMEOUT` | `15` | Request timeout in seconds |
| `INTEGRATION_RETRIES` | `2` | Retries for a queued request (tries = retries + 1) |
| `INTEGRATION_AUDIT_REQUEST_BODY` | `false` | Store the outbound body in the audit |
| `INTEGRATION_AUDIT_RESPONSE_BODY` | `false` | Store the response body in the audit |
| `INTEGRATION_AUDIT_MAX_BODY` | `2000` | Bytes kept of a stored body |
| `INTEGRATION_AUDIT_RETENTION_DAYS` | `90` | Days an audit row is kept |
| `INTEGRATION_RATE_LIMIT_STORE` | (empty) | Cache store for rate-limit counters |
| `INTEGRATION_RATE_LIMIT_PREFIX` | `integration_rl` | Key prefix for the counters |
| `INTEGRATION_CACHE_STORE` | (empty) | Cache store for response caching |
| `INTEGRATION_CACHE_TTL` | `60` | Response cache lifetime in seconds |

`audit.redact_headers` (not env-backed) lists the headers stripped from every summary: `authorization`, `x-api-key`, `cookie` and `set-cookie`.
