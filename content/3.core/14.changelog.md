Core follows [Semantic Versioning](https://semver.org/) and is versioned on its own, independently of the starter kit. Its `CHANGELOG.md` lives in `packages/core` and follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The kit's own [changelog](/releases/changelog) records which Core version each kit release requires.

Core releases are tagged `core-v<semver>` in the kit's repository; see [Package releases](/releases/packages).

## 1.1.0 - 2026-10-25

### Added

- **Feature sources.** A `FeatureSource` tagged `FeatureManager::SOURCES` decides a feature after the per-tenant and global overrides and before the config default, given a `FeatureScope` with the tenant and the acting user. `FeatureManager` gains `enabledFor()`, `resolutionFor()` (a `FeatureResolution` naming the deciding `FeatureLayer`) and `flush()`, and `feature:list` shows which layer decided. With no source registered nothing changes, and the guard is never asked for the user. See [Features](/core/features#feature-sources).
- **`StagePreset`.** The write and read presets as `StagePreset::WRITE` and `READ`, and `insert(...)->before()` / `after()`, with `reads()` or `both()`, for a package to add a stage to every service on a preset. Insertions are placed before `stagesWithout()` filters the preset and are checked once the application has booted. See [Service pipeline](/core/service-pipeline#inserting-into-a-preset).

## 1.0.0 - 2026-10-24

### Added

- **First release** of Core as its own package, extracted from the starter kit's `app/Core` into the `Rollogi\Core` namespace: the service pipeline and its stages, actions and queued execution, single-database tenancy and per-tenant settings, feature toggles, RFC 9457 problem responses and the HTTP middleware, auditing, the reshaped Spatie permission tables, outbound integrations on Saloon, inbound webhooks, metrics, search indexing, health checks, module discovery, the `make:module` and `make:use-case` generators, the PHPStan extensions and the layering checks.
- **`modules.php`** (`path`, `namespace`, `tests_path`): where `ModuleServiceProvider` discovers modules and where the generators write, defaulting to `app/Modules`, `App\Modules` and `tests/Feature`. `Rollogi\Core\Support\ModuleLayout` reads it. See [Package modules](/core/package-modules#the-modules-config).
- **`@internal` marking.** Classes Core wires up itself are marked `@internal` and are not covered by semantic versioning. See [the public API](/core#public-api).

::note
Upgrading Core from 1.0 to 1.1 needs no code change: both additions are opt-in, and 1.1 behaves exactly as 1.0 until a package registers a feature source or a stage insertion.
::
